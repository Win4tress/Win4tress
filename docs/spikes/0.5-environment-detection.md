# Spike 0.5: Environment detection

**Status:** Partly passed (2026-10-25). Every check runs and reads this PC's state correctly, without elevation. The cases that matter (a third-party firewall, a Group Policy that disables local rules or forces the outbound default) can't be produced on the dev PC and need the test VM.
**Tool:** [tools/spikes/fw-probe](../../tools/spikes/fw-probe) (`fw-probe env --out <dir>`, read-only; run both elevated and as a standard user)
**Machine:** Windows 11 Enterprise VM (the dev PC): Windows Firewall on for all profiles, outbound default allow, Microsoft Defender Antivirus, no Group Policy or MDM firewall settings

## Findings

1. **No elevation needed.** A standard user gets the same results, so the UI can show the environment even when the service is down.
2. **Windows Firewall lists itself in Security Center** with product GUID `NULL`. Recognise Windows' own entry by that, not by its name, which may be translated. The probe matched on the name; the service shouldn't.
3. **Two ways to see a policy.** `LocalPolicyModifyState` reports whether Group Policy overrides local settings, and the registry policy keys say which settings. The service should use both: the COM value for the decision, the registry for the explanation in the banner.
