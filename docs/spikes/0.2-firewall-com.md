# Spike 0.2: Windows Firewall rules from Rust (COM)

**Status:** Passed (2026-10-25). 36 checks, none failed. The WMI fallback isn't needed.
**Tool:** [tools/spikes/fw-probe](../../tools/spikes/fw-probe) (`fw-probe run --out <dir>`, elevated)
**Machine:** Windows 11 Enterprise VM, Rust 1.99, `windows` 0.62.2. Firewall on for all profiles, inbound default block, outbound default allow, no Group Policy override (modify state 0), 660 rules at the start.

Every rule the probe made was in the group `win4tress spike` and was removed at the end; none were left. Rules that blocked anything applied only to a private copy of `curl.exe`. Blocking was checked by having that copy connect to `https://1.1.1.1/` and `https://8.8.8.8/` (by IP, so DNS played no part).

| Time per change and per batch | See below | ✅ measured |

Also checked: a block rule beats an allow rule for the same app (as documented), and inbound rules are created and read back.

## Findings that change the design

1. **Rule names must be unique, so the name includes our rule ID.** Windows allows several rules with the same name; `Remove(name)` removes only one of them (two same-named rules → one left), and `Item(name)` returns only the first. Two apps can share a display name (svchost instances, two installs of one program), so the SPEC §7.2 name `win4tress: <App name> (<In|Out>, <Allow|Block>)` gets the rule ID appended. Clean-up and uninstall enumerate the group and repeat until it's empty, rather than trusting one `Remove` per name.
2. **Windows rewrites addresses on read-back.** `8.8.8.8` comes back as `8.8.8.8/255.255.255.255`. Reconciliation compares parsed address sets, never the strings we wrote.
3. **Reconciliation is cheap.** Reading every field of all ~870 rules takes 26 ms, so the 60-second tamper diff (SPEC §7.8) can simply re-read the whole set.
4. **Bulk changes take seconds, deletes are the slow part.** 200 removals take 2 s. "Apply" for a large selection, "Reset" and uninstall must run off the UI path and show progress; prefer disabling the group (one call, 36 ms) when only switching enforcement off.
5. **Large address lists are fine.** A complement list for "allow only these hosts" and per-host lists in the thousands are well within limits (10,000 addresses: 104 ms, 293 KB). Inline address lists remain a sound baseline whatever spike 0.3 finds.
6. **Changes take effect immediately.** No delay was measurable between `Add`/setter returning and the next connection being blocked or allowed, so the UI can confirm a change as soon as the call returns.
7. **Reading rules needs no elevation.** Writing does. All writes stay in the service; this just means read-only diagnostics could work from an unelevated tool.
